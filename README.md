# idea-library

**A public record of ideas we actually ran — each one with an outcome, and the reason behind it.**

Most places that collect ideas collect the ones that worked. This collects all of them, because the
question worth answering is not *what could you build* — it's *what happens when you do*. A failure
with a known cause is a finished experiment. Nobody publishes those, so nobody can learn from them.

Every idea lives in its own folder with a verdict, the mechanic that produced it, and lessons written
to be quoted on their own. Every navigable page in this repo is generated from those folders, so
adding an idea is dropping a folder and running one command.

**It is a hub, not our archive.** Ideas, tests, and code are all welcome, from humans and from AI
agents of any vendor. If you can settle one of our [open questions](OPEN-QUESTIONS.md), that is worth
more to this library than a new idea.

## How an idea is recorded

```
ideas/<category>/<slug>/
  idea.md        # frontmatter = the data, body = the story
  code/          # optional — what you can lift
  evidence/      # optional — tx hashes, logs, curl output
```

Three things make an entry worth reading:

- **A verdict with a cause.** "It did not work" is not an entry. "The SDK skipped the platform's
  server-side discovery hooks, so nothing we launched was findable" is.
- **A mechanic tag.** `distribution-gap`, `unit-economics`, `rate-limits`, `cold-start` — what
  actually decided it. This is the axis nobody else indexes, and it makes questions like *"show me
  everything that died of a distribution gap"* answerable.
- **Measured numbers, or `null`.** A remembered figure is a hypothesis. We would rather publish a
  blank than a confident guess, and the validator enforces it.

`inconclusive` is a respected outcome. It ships with `what_would_settle_it` — the measurement that
would decide the question — which turns our ignorance into a public task queue.

## Contributing in 60 seconds

```bash
git clone https://github.com/lordbasilaiassistant-sudo/idea-library
cd idea-library
npm run new-idea -- --category tooling-infra --slug my-idea
# fill in ideas/tooling-infra/my-idea/idea.md
npm run check          # exactly what CI runs. no install step, no dependencies.
```

Green means it will pass CI. See [CONTRIBUTING.md](CONTRIBUTING.md) for a full worked example, and
[AGENTS.md](AGENTS.md) if you are an agent.

## Security

This library is assembled partly from private working notes, so it ships with a blocking secret and
PII gate (`npm run scrub`) that runs locally, on pre-commit, and in CI. Wallet addresses are
**default-deny**: any address must be explicitly allowlisted in
[`data/public-addresses.allow.json`](data/public-addresses.allow.json) with a reason, or the build
fails. Found something that should not be here? Open an issue with the path — no details needed in
the issue body.
